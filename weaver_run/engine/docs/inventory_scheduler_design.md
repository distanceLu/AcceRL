# AcceRL-WM：双版本约束下的库存前瞻与固定拓扑调度

研究及本地候选日期：2026-11-02。本文区分论文已证明的机制、项目观测、
本次实现和后续研究假设。没有部署新训练，没有声称 GPU 提速已经验证。

## 1. 为什么不能只继续调权重

父运行 `weaverintegrated_1030_181824_cf621e5b` 完成 P868/W173，约63.03小时。
原始证据和可复算统计位于
`../../analysis/weaver_scheduler_performance_20261102/performance_analysis.json`。
P21–P100的完整周期为1350.59秒，约13.33次Policy更新/小时；旧FRESH对应
窗口约906秒、19.87次/小时。这不是随机化A/B，不能独立归因于调度算法。

新运行普通Policy训练已由65.56秒降至53.64秒，但取样、等待和刷新由78.66秒
增至179.61秒。210次有记录的缺货更新合计至少等待22.66小时；这与部分World
工作重叠，不能将其全部换算为可消除的墙钟时间。后期四路想象lease占用率
约37.8%，入池约0.426 chunk/秒。生产准入不放行时，提高World服务权重不能
凭空产生可执行工作。

具体断点：credit耗尽后进入pause，正常恢复要求积累2048 credit；一次更新
的432次想象draw仅返还108 credit。原修复只在下一批真正缺货时允许提前花
已有credit，于是容易形成每几次更新集中补货的停顿。新候选保留这条紧急
路径，增加有界、提前发生的补货需求。

## 3. 研究对象：未来可用容量，而非物理Replay长度

每条样本i记录：生成Policy版本p_i、World/RM版本w_i、成功使用次数u_i、
已预约消费r_i。保留原来的四次使用上限，剩余容量为：

```text
c_i = max(0, 4 - u_i - r_i)
valid(i,j) = 0 <= p_j - p_i <= 16 AND 0 <= w_j - w_i <= 3
```

真实样本没有World版本条件。本次实现仅预测想象补货，真实数据生产和真实
144条配额保持原规则；实际抽样仍同时检查两种来源，不能用想象补真实缺口。

下一步j需要432条不同的想象chunk。令x_ij表示样本i在未来批次j出现一次：

```text
x_ij in {0,1}; x_ij <= valid(i,j)
sum_j x_ij <= c_i
sum_i x_ij = 432 for each future batch j
```

所以不能仅看“remaining uses总和是否超过432”。108条各剩四次的样本，
依然无法满足一次432条不同样本的抽样。相反，432条只剩一次的样本，配合
216条新样本，在可重新组合的情况下具有两个批次的可行容量。

实现按“剩余次数、未来版本有效掩码”归组，用一个小的整数最大流图估算
可行容量：源到组的容量为组内总剩余次数，组到每批的容量为组内样本数，
每批到汇的容量为432。二分求需新增的chunk数，最多432。等价组具有相同
可用批次和每样本容量，这个聚合保留了每批不同样本的容量限制。

这只是可行容量预测，**不是实际随机抽样的可行性保证**。候选不改变原有
uniform sampling，不为未来批次预留具体样本；随机抽样、容量驱逐、推理
延迟和样本失效都可能让预测失准。闭环周期性重算，原缺货反馈和真正的
SegmentReplay.reserve始终保留最终决定权。

## 4. 本次实现

- `inventory_lookahead.py`：只读容量预测、短期准入建议、Replay异步反馈循环。
- `pipeline_budget.py`：暂停时按前瞻需求提前花已有credit。总credit、每seed
  扣款、退款和全局四个在途lease仍由原单一owner维护。
- `pipeline_runtime.py`：将消息传递到已有WM Replay预算owner。
- `train.py`：显式启动、健康检查、正常停止收尾与事件记录。
- `fresh_replay_pressure.py`：等待当前批次时检查控制循环是否失败。
- 两份独立pipeline配置与四组合启动器：关闭/打开前瞻 × 固定/自适应权重。

默认horizon=0，实验配置启用2；允许1–4做后续消融。预测版本是当前已发布
版本之后的h个发布位置。仅在W=floor(P/5)时预测，联合发布的中间状态暂停
建议；实际下一批可能仍使用发布前版本，因此该年龄预测是偏保守的。

每0.5秒最多发送一次，消息绑定版本、递增revision和同一主机的monotonic
观察时间；两秒过期。版本发布清除旧建议。RPC最多一个并发，超时沿用
已有有界owned-RPC机制，失败向训练显式传播，不无限重试。停止时取消循环
并发送更高revision的清除消息；乱序旧消息不能复活已经撤销的建议。

单次建议量扣除观察后已完成的生产和当前在途预留量。Replay入池ACK早于
producer完成记账的小窗口可能保守地重复扣除一个在途lease，最多涉及在途
的16个chunk；这倾向短暂少放行，下一次快照重新校正。每seed四个chunk的
粒度可能造成最多三个尾部chunk超额。两个反馈源不能分别发credit。

本次没有实现新的MPC权重搜索、推理batch2/4、Eval配额或训练microbatch
抢占。现有自适应权重控制器保留，可以利用新产生的可执行生产任务。其
权重仍不是SM配额，不能假设2倍权重对应2倍速度。

## 5. 后续真正的算法方向

建议把论文问题收紧为：**固定并行拓扑下，同时考虑双版本有效期、样本复用
额度与训练依赖的生产准入和GPU服务调度。** 本次实现的是可独立检验的
库存前瞻部件，不是已经完成、已经证明优于RLinf的整套论文算法。

下一层控制器可同时选择生产放行量a和服务权重w，最小化实测模型预测的
下个完整5:1周期完成时间，加上样本失效成本和切换惩罚。根据生产完成时间
与训练需求截止点决定前瞻长度，而不是永远固定两次更新。实测模型应保留
同卡竞争的非线性，分开普通轮和联合轮，并对预测误差设置保守余量。

明确约束：旧信用上限、真实144/想象432、年龄16/3、最多4次成功消费、
内存与在途上限、所有rank统一放行、当前critic版本一致。安全边界以内可
借用空闲份额；不能删除校验或用放松算法规则伪装系统提速。

主目标不直接用训练reward或滚动Eval反馈逐请求资源；先用固定条件独立
评估验证学习效率，再研究稳健的统计效率代理。Pollux的goodput思想可借鉴，
但没有现成的、已验证适用于我们WM联合训练的统计效率估计器。

## 6. 可证伪的验收与论文实验

先做四组相同起点、相同学习规则的2x2实验：

| 组 | 生产准入 | 服务权重 |
|---|---|---|
| A | 当前缺货反馈 | 固定 |
| B | 加两次更新的前瞻 | 与A相同固定权重 |
| C | 当前缺货反馈 | 现有自适应 |
| D | 加两次更新的前瞻 | 与C相同自适应算法 |

B–A检验提前生产，D–C检验在原系统上的增益；两者差异检验是否存在交互。
先跑足够多完整5:1周期，排除冷启动，保留所有失败及skip，不挑最快片段。
至少覆盖数十完整周期和多个初始化种子；完整学习比较需要相同真实sim预算，
同时报告同墙钟和同更新次数，不能靠跑更久获得优势。

必须记录：

1. 完整周期、真实缺货等待、GAE刷新、训练和发布的壁钟分解，阶段重叠不能相加。
2. 新入池速度、生产lease占用率、有效消费、逐样本成功复用分布、版本/时间年龄。
3. 因年龄/容量丢弃的样本及其未用额度、每个生产暂停原因、credit资金不足。
4. 前瞻预测缺口与实际缺口、RPC延迟/拒绝/TTL过期、控制CPU成本。
5. 整周期显存峰值，包含联合训练、发布与保存；资源/电耗按共同墙钟核算。
6. 独立固定评估达到90%/95%的时间和真实sim调用数。每次评估完整收齐
   固定episode集合，greedy/stochastic分开，不能使用按完成先后混合的滚动均值。

固定task0同50初态上的50/50不能证明其他task或未见初态泛化。论文需要
更多任务、多个种子、置信区间，并与简单水位线预取、只看credit、只看Policy
年龄、固定权重等强基线比较。若引用RLinf/ReaL的性能，必须用共同模型、
数据、GPU预算和学习规则，无法统一时明确报告差异，不做虚假公平排名。

按四次消费的理想上界，19.87次更新/小时需要约0.596新想象chunk/秒。
这是供需检查值，不是保底产出；实际有效平均复用可能小于4。旧运行的活跃
生产速率提供了探索理由，但提前生产也可能干扰训练，只有上述实验能回答
最终是否缩短达到目标效果的时间。

如果B/D没有减少等待、样本失效增加、或者训练干扰抵消供给收益，应否定
“当前前瞻配置有收益”的假设，调整截止点/成本模型，而不是提高复用上限。
