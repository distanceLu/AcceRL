# 真实训练150动作正式失败，评估仍为220动作

2026-11-10，用户授权停止旧150动作预算截断实验、跳过该次最终评估，并以150动作正式任务终点启动新实验。此文描述新代码规则，不表示新进程已经启动；实际启动、停止和跳过评估状态以对应实验队列回执为准。开发继续使用同一Git仓库和分支，不改写旧实验或历史标签。

## 新规则

`weaver_run/recipe/pipeline_config.json` 设置 `real_training_action_horizon:150` 和显式 `real_collection_action_limit:null`。真实训练任务要求150个动作内成功；额外的采集预算上限关闭。基础LIBERO任务及评估上限仍为220动作，想象horizon保持32动作。10个reset step照常计入累计1M模拟调用预算，不计入150个任务动作。

- 150动作内成功（包括最后一个动作成功）：记录成功，按实际成功时刻生成dense目标。
- 完整执行150动作仍未成功：记为正式训练任务失败。RM有效标签为0，目标mask有效；Policy按任务终止处理，末端不bootstrap。World仍可学习已观察到的真实前缀。
- 累计1M模拟预算不足、在150动作任务终点之前被截断：结局未知，继续使用原budget censor语义；RM整段mask0，Policy末端bootstrap。不能把没有观察到结果的前缀伪标为失败。
- 在线Eval和最终固定评估继续执行最多220动作。训练任务horizon只作用于真实训练采集，不缩短评估。

Policy仍每8动作重新获取观测；最后一个chunk最多执行剩余6动作，未执行尾部不计入Policy surrogate、KL或entropy。该改动没有新增抓取检测、闭环重抓控制器或逐动作重规划。

## 与旧150动作预算截断实验的区别

| 情况 | 2026-11-09旧规则 | 2026-11-10新规则 |
| --- | --- | --- |
| 真实训练任务终点 | 220动作 | 150动作 |
| 额外采集上限 | 150动作预算 | 无额外上限（null） |
| 执行150动作仍未成功 | 未知结果、预算截断 | 正式任务失败 |
| 上述episode的RM目标 | mask0，不作为已知失败监督 | 有效零标签 |
| 上述episode的Policy末端 | bootstrap | terminal，不bootstrap |
| 累计模拟预算提前耗尽 | budget censor | budget censor，保持原规则 |
| 在线/最终评估上限 | 220动作 | 220动作 |

新规则改变了学习任务的时间范围，不只是运行时优化。训练成功率的统计口径也相应变化；新旧效果比较应固定相同Policy checkpoint评估方案、同一50初态和220动作上限。不能仅凭新训练曲线判断收敛改善，也不能把50个初态说成50个不同任务。
